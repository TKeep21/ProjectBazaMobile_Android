# Политика кэширования новостей (ДЗ3+4)

## Что кэшируется
1. Список новостей NYT (`news_list.json`) во внутреннем хранилище приложения.
2. Превью-изображения новостей (`files/news_image_cache`) + метаданные в SQLite (`news_image_cache.db`).

## Сервисы
1. `NewsRemoteDataSource` — только сеть (получение списка новостей).
2. `NewsListCacheDataSource` — только файловый кэш списка новостей.
3. `NewsImageCacheDataSource` — кэш изображений (файловая система + SQLite).
4. `NewsRepository` — единая точка, где применяются правила чтения/обновления/очистки.

## Политика для списка новостей
1. Экран делает сетевой запрос при открытии и далее каждые 2 минуты.
2. При успешной сети кэш списка перезаписывается полностью.
3. При ошибке сети используется сохраненный кэш (fallback), если он не старше 24 часов.
4. Кэш старше 24 часов автоматически удаляется.

## Политика для изображений
1. Для URL изображения ищется запись в SQLite и соответствующий файл.
2. Если файл свежий (TTL 6 часов), используется локальная копия без сети.
3. Если файл устарел, делается попытка скачать новую версию и обновить кэш.
4. Если загрузка не удалась, можно показать старую копию (не старше 7 дней).
5. Очистка:
   - удаляются записи старше 7 дней;
   - применяется LRU-очистка при превышении лимитов (40 MB или 200 файлов).

## Почему так
1. Пользователь видит новости сразу (быстрый старт из кэша), UI не блокируется.
2. Каждые 2 минуты данные остаются актуальными.
3. При нестабильной сети экран продолжает работать за счет fallback.
4. Автоочистка не дает кэшу бесконтрольно расти.
